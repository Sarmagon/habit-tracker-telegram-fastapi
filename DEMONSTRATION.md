# Сценарий демонстрации для куратора

Цель: показать работу текущего приложения, реальные ответы API и затем Telegram-интерфейс. Не выдавайте API-демонстрацию или имитацию Telegram за запись реальной переписки. JWT, service secret и BotFather token скрывайте на видео.

## Часть 1. Контейнеры и Swagger / API

1. Открыть папку проекта. Показать `.env.example` и команды запуска без открытия заполненного `.env`.
2. Выполнить `docker compose up -d --build backend`. Показать `docker compose ps`: initialize завершён, database healthy, backend healthy. Бот без настоящего token на этом этапе не запускается.
3. Показать `docker compose logs --tail=30 backend`, `docker compose exec backend alembic current`, `docker compose exec backend alembic check`.
4. Открыть `/docs`. Показать endpoints, схему UserAccessToken, Try it out и ответы. Без Authorize запросить список: 401.
5. Получить JWT отдельного тестового пользователя через `scripts.issue_swagger_token` вне записи. Авторизоваться в Swagger (поле JWT скрыто), запросить список: 200.
6. Создать привычку: 201. Просмотреть список. Изменить название/описание/даты: 200.
7. Отметить выполненной: 200, счётчик 1. Повторить: счётчик остаётся 1. Отметить невыполненной: счётчик 0. Показать историю.
8. Проверить пустое название, неверный диапазон дат, неизвестный timezone: 422. Проверить вчерашнюю дату отметки: 409.
9. Войти другим тестовым пользователем: изменить/удалить/прочитать историю чужой привычки: 404.
10. Передать просроченный JWT: 401. Показать тест обновления/сохранения token store после перезапуска — это проверка модели бота, не запись Telegram.
11. Удалить привычку: 204. Показать пустой список и 404 для удалённой истории.
12. Показать `poetry run pytest -q`, линтер и результаты PostgreSQL checks / GitHub Actions.

## Часть 2. Реальный Telegram после настройки BotFather token

1. Создать бота через @BotFather вне записи, сохранить token в `.env`. Не присылать token куратору и не открывать его на экране.
2. Запустить `docker compose up -d --build`. Показать bot healthy и открыть личный чат.
3. `/start`, `/help`, `/add`: пройти создание, включая неверную дату и исправление ввода. `/cancel` показать отмену диалога.
4. `/today`: показать карточку и каждую отметку, включая повтор. `/all`: будущая привычка и освоенная. **Изменить**, **История**, **Удалить** и подтверждение.
5. `/reminder`: назначить ближайшую минуту, указать правильный timezone и включить напоминания. Дождаться реального сообщения; затем показать выключение.
6. После пользовательского действия проверить в SQLite только ID, время истечения и количество записей; не выводить ciphertext/ключ/token. Перезапустить `docker compose restart bot`; показать, что база сохранена и `/today` продолжает работать.
7. Для проверки перевыпуска выставить `ACCESS_TOKEN_MINUTES=1`, пересоздать backend и bot, подождать >60 секунд и выполнить запрос. Показать новый `updated_at` и действующий запрос без вывода JWT. Затем вернуть 15 минут.
8. В отдельном учебном запуске с `HABIT_COMPLETION_LIMIT=1` показать достижение лимита, дневной перенос тестом и сохранение истории. Не менять часы компьютера ради демонстрации.
9. Старую кнопку предыдущего дня проверить на реальной следующей дате либо отдельным API-запросом с прошлой датой (явно пояснить способ).

## Отправка

Сохранить видео отдельным `.mp4`, не упаковывать в ZIP. Если форма не принимает размер, загрузить файл в выбранное пользователем хранилище и включить доступ по ссылке. Полную финальную сдачу отправлять после записи обеих частей. Для промежуточной сдачи честно указать, что готов API, а демонстрация Telegram ещё планируется.
