# Запись демонстрации Habit Tracker

Гайд для вашего проекта и бота **@SarmagonHabitTrackerBot**. Каждый шаг содержит три действия. Привычки «Читать 15 страниц» и «Пить воду» оставлены на месте. Для записи создайте отдельную привычку **Видео: зарядка** и удаляйте только её.

Можно записать три отдельных MP4: запуск и проверки, Telegram, Swagger. Передайте исходные видео без ZIP. Запись должна показывать ваши реальные действия. Не открывайте `.env`, чат BotFather или содержимое JWT/ключей на записи.

## Подготовка — вне записи

### Шаг 1. Открыть проект

1. Откройте Проводник и вставьте в адресную строку: `C:\Users\!\Documents\Codex\2026-10-02\referenced-chatgpt-conversation-this-is-an\outputs\habit-tracker`.
2. Щёлкните по пустому месту папки правой кнопкой → **Открыть в Терминале**. Используйте вкладку PowerShell.
3. Вставьте и выполните команду ниже — она создаёт короткую команду `dc` только в этом окне:

```powershell
function dc { docker --config "../../work/docker-config" compose @args }
```

Обычная команда запуска проекта — `docker-compose up` / `docker compose up`. Здесь `dc` сокращает её и указывает уже настроенное локальное соединение Docker.

### Шаг 2. Подготовить Telegram

1. Откройте чат **@SarmagonHabitTrackerBot**.
2. Закройте боковую панель эмодзи и включите «Не беспокоить», чтобы личные уведомления не попадали на видео.
3. Отправьте `/start` и убедитесь, что видны кнопки **Сегодня**, **Добавить привычку**, **Все привычки**, **Напоминания**, **Помощь**.

### Шаг 3. Начать запись

1. Нажмите **Win + Shift + R**; если сочетание не сработало, откройте **Ножницы** через Пуск и выберите значок видеокамеры → **Создать**.
2. Выделите область экрана, в которой будете показывать терминал, Telegram и браузер.
3. Нажмите **Начать**. Если удобно, комментируйте действия голосом.

Официальная инструкция записи: [Microsoft — Ножницы](https://support.microsoft.com/en-us/windows/apps/use-snipping-tool-to-capture-screenshots).

## Видео 1. Запуск и проверки

### Шаг 4. Показать запуск

1. В терминале выполните `dc stop` — данные и volume сохраняются.
2. Выполните `dc up -d --build` и покажите результат запуска.
3. Выполните `dc ps -a`: database, backend и bot должны быть **healthy**, initialize — **Exited (0)**.

### Шаг 5. Показать backend и миграции

1. Выполните `dc logs --tail=20 backend` — покажите запуск API и обработанные запросы.
2. Выполните `dc exec backend alembic current` — ожидается `0001 (head)`.
3. Выполните `dc exec backend alembic check` — ожидается `No new upgrade operations detected`.

### Шаг 6. Показать автоматические проверки

1. Выполните `../../work/venv/Scripts/ruff.exe check .` — ожидается `All checks passed!`.
2. Выполните `../../work/venv/Scripts/python.exe -m pytest -q` — ожидается **47 passed, 1 skipped**; PostgreSQL-тест выполняется отдельно в GitHub Actions.
3. Откройте [GitHub Actions](https://github.com/Sarmagon/habit-tracker-telegram-fastapi/actions), покажите зелёный запуск последней версии. При необходимости раскройте этап PostgreSQL migration checks.

Скажите: «Проверены шифрование и сохранение токенов, их перевыпуск, разграничение доступа, перенос на следующий день и конфигурируемый лимит выполнений». Перенос на завтра проверяется тестом с заданным временем; часы компьютера не меняются.

## Видео 2. Telegram

### Шаг 7. Показать меню

1. Отправьте `/start` — покажите приветствие и постоянные кнопки.
2. Нажмите синюю кнопку **Меню** слева от поля ввода — покажите зарегистрированные команды.
3. Закройте список команд и нажмите **Сегодня** — покажите существующие привычки.

### Шаг 8. Начать создание

1. Нажмите **Добавить привычку**.
2. На запрос названия отправьте `Видео: зарядка`.
3. На запрос описания отправьте `Делать зарядку 5 минут`.

### Шаг 9. Показать ошибку и исправление даты

1. На запрос даты начала отправьте `2026-02-30` — покажите понятную русскую ошибку.
2. Нажмите **Сегодня** — бот продолжит тот же диалог.
3. На запрос даты окончания нажмите **Без ограничения** — покажите сохранённую карточку.

### Шаг 10. Проверить отметку

1. Под карточкой **Видео: зарядка** нажмите **✅ Выполнено** — счётчик станет 1.
2. Под последней карточкой этой привычки снова нажмите **✅ Выполнено** — счётчик останется 1.
3. Нажмите **История** под этой привычкой — покажите сегодняшнюю запись «выполнено».

### Шаг 11. Исправить отметку

1. Под последней карточкой **Видео: зарядка** нажмите **❌ Не выполнено** — счётчик станет 0.
2. Нажмите **История** под новой карточкой — покажите «не выполнено» за сегодня.
3. Нажмите **Все привычки** — покажите, что история и привычка сохранены.

### Шаг 12. Начать редактирование

1. Нажмите **Изменить** под карточкой **Видео: зарядка**.
2. Отправьте новое название `Видео: зарядка 10 минут`.
3. Отправьте новое описание `Делать зарядку 10 минут`.

### Шаг 13. Сохранить изменения

1. На запрос даты начала нажмите **Сегодня**.
2. На запрос даты окончания нажмите **Без ограничения**.
3. Нажмите **Сегодня** в главном меню и покажите обновлённое название и описание.

### Шаг 14. Показать отмену ввода

1. Нажмите **Добавить привычку**.
2. Отправьте название `Не сохранять`.
3. Нажмите **Отменить** — диалог закрывается, главное меню возвращается, новая привычка не создаётся.

### Шаг 15. Начать настройку напоминания

1. Нажмите **Напоминания**.
2. На запрос времени отправьте `25:70` — покажите русскую подсказку.
3. Отправьте время **на 2–3 минуты позже текущего времени в Москве**, строго `ЧЧ:ММ`, например `22:35`. Пример не копируйте, если это время уже прошло.

### Шаг 16. Сохранить напоминание

1. На запрос часового пояса отправьте `Wrong/Timezone` — покажите ошибку.
2. Нажмите **Europe/Moscow**.
3. Нажмите **Да** — покажите подтверждение сохранения.

Важно: **«Пить воду» должна оставаться сегодня без отметки**. Напоминание отправляется о привычках, которые ещё не отмечены. «Не выполнено» — уже явная отметка, поэтому только такой привычки для демонстрации напоминания недостаточно. Если у воды уже есть отметка, создайте новую привычку «Видео: напоминание», используя шаги 8–9 с кнопкой **Пропустить** вместо описания.

### Шаг 17. Показать реальную доставку

1. Дождитесь назначенной минуты и ещё до 15–30 секунд — должен прийти текст **«Пора отметить привычки»**.
2. В напоминании нажмите **Открыть привычки** — появятся карточки с кнопками отметок.
3. Нажмите **История** под «Пить воду», чтобы показать переход от напоминания к данным; оставьте воду без отметки для возможного повторного дубля записи.

При изменении времени или включении напоминаний они ставятся заново. При сохранении тех же настроек повтор за день не создаётся. Сбой Telegram приводит к повторной попытке не раньше чем через 60 секунд.

### Шаг 18. Показать перезапуск

1. Переключитесь в терминал и выполните `dc restart bot`.
2. Вернитесь в Telegram и нажмите **Сегодня**; если бот ещё запускается, подождите несколько секунд и нажмите снова.
3. Покажите, что привычки и отметки сохранились. В видео 1 уже показаны тесты, доказывающие сохранение зашифрованного JWT после перезапуска и его автоматический перевыпуск; сам токен на экран не выводится.

### Шаг 19. Показать отмену удаления

1. Нажмите **Удалить** под **Видео: зарядка 10 минут**.
2. Нажмите **Оставить привычку** — покажите отмену.
3. Нажмите **Сегодня** — привычка осталась в списке.

### Шаг 20. Удалить тестовую привычку

1. Нажмите **Удалить** под **Видео: зарядка 10 минут**.
2. Нажмите **Подтвердить удаление**.
3. Нажмите **Сегодня** — тестовая привычка исчезла, остальные остались.

## Видео 3. Swagger и доступ к API

### Подготовка JWT — без записи

1. В открытом PowerShell выполните команду ниже: токен попадёт в буфер обмена, а не в вывод терминала.
2. Откройте `http://127.0.0.1:18080/docs`.
3. Пока **не нажимайте Authorize**: сначала запишите отказ без JWT.

```powershell
$taskSwaggerToken = dc exec -T bot python -m scripts.issue_swagger_token --telegram-id 9000000000200
if ($LASTEXITCODE -eq 0) { Set-Clipboard -Value ($taskSwaggerToken.Trim()) }
```

JWT действует 15 минут. Если запись затянется, получите новый токен той же командой вне записи. Это отдельный демонстрационный пользователь Swagger; его данные не являются вашими Telegram-привычками. CLI — инструмент доверенного оператора, а не общедоступный вход по произвольному ID.

### Шаг 21. Показать отказ без токена

1. Начните запись Swagger и раскройте **GET /api/v1/habits**.
2. Нажмите **Try it out** → **Execute**.
3. Покажите **Server response: 401** и текст «Требуется токен».

### Авторизация — без показа значения JWT

1. Остановите этот фрагмент записи и нажмите **Authorize**.
2. Вставьте JWT из буфера без слова `Bearer`, нажмите **Apply credentials** и убедитесь, что видны **Authorized** и скрытое значение `******`.
3. Возобновите запись на этом безопасном экране, покажите схему **UserAccessToken (HTTP Bearer JWT)**, затем нажмите **Close**.

В ответах Swagger блок **Curl** содержит JWT. Перед исполнением авторизованного запроса остановите запись, выполните запрос, прокрутите к **Server response** ниже Curl и только затем возобновите запись. Не показывайте строку `Authorization: Bearer ...`. Удобно сохранить несколько небольших исходных MP4.

### Шаг 22. Создать привычку API

1. Раскройте **POST /api/v1/habits**, нажмите **Try it out**, вставьте JSON ниже. Подставьте сегодняшнюю дату по Москве.
2. Вне записи нажмите **Execute**, прокрутите ниже Curl до **Server response** и возобновите запись.
3. Покажите **201**, тело ответа и запомните `identifier` этой привычки.

```json
{"title":"Видео API","description":"Проверка Swagger","start_date":"2026-10-06","end_date":null}
```

### Шаг 23. Просмотреть и изменить API-привычку

1. Выполните **GET /api/v1/habits** и покажите **200** со своей привычкой (соблюдайте правило скрытия Curl).
2. В **PUT /api/v1/habits/{habit_identifier}** укажите сохранённый identifier и JSON с названием `Видео API — изменено`, теми же датами и описанием.
3. Выполните запрос и покажите **200** с новым названием.

### Шаг 24. Отметить через API

1. В **POST /api/v1/habits/{habit_identifier}/completion** укажите identifier, в тело вставьте `{"completed":true,"record_date":"СЕГОДНЯ-ГГГГ-ММ-ДД"}`, заменив дату настоящей. Покажите **200**, `completion_count: 1`.
2. Повторите запрос — счётчик должен остаться **1**.
3. Выполните **GET /api/v1/habits/{habit_identifier}/history** — покажите историю.

### Шаг 25. Показать ошибки

1. В POST создания отправьте JSON с `"title":""` — покажите **422**.
2. В POST completion отправьте **вчерашнюю** дату — покажите **409**.
3. В GET history укажите `habit_identifier=999999999` — покажите **404**.

### Шаг 26. Показать разграничение пользователей

1. Вне записи получите JWT второго пользователя командой подготовки, заменив `9000000000200` на `9000000000201`.
2. Вне записи в **Authorize** нажмите **Remove authorization**, вставьте новый JWT, нажмите **Apply credentials**, **Close**.
3. Запросите историю identifier, созданного первым пользователем; после скрытия Curl покажите **404**. Скажите: «Валидный токен другого пользователя не даёт доступ к чужой привычке».

### Шаг 27. Удалить API-привычку

1. Вне записи верните JWT первого пользователя (`9000000000200`) тем же способом.
2. Выполните **DELETE /api/v1/habits/{habit_identifier}** с его identifier — после скрытия Curl покажите **204**.
3. Выполните **GET /api/v1/habits** — покажите отсутствие удалённой API-привычки.
